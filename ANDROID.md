# Alderwick for Android

The Android build is a separate landscape project generated by `python tools/prepare_android.py`. It leaves the desktop game unchanged. The private repository's **Build Android** workflow creates a signed debug ARM64 APK for direct installation; this is not a Play Store release.

The phone profile targets a Redmi 15 conservatively: Performance caps rendering at 30 FPS, Balanced at 45 FPS, and High/Ultra at 60 FPS. Performance animates nearby residents within 22 metres; their routines keep running farther away. Actual sustained FPS requires testing on the phone. Embedded GLB textures are resized to at most 512 pixels in the staged Android copy; mesh, rig, and animation buffers remain unchanged. Generated duplicate GLB image files are excluded from staging. Install Pillow to prepare Android locally (`python -m pip install Pillow`).

Touch movement uses a round left joystick, free looking on the right, and separate native multitouch action buttons, following Riftwatch's layout. Moving, looking, and jumping can be held with separate fingers. Android is detected through its OS name, feature tag, and mobile export feature. Desktop mouse capture is disabled on phones.

A loading screen shows world and resident setup progress. On the first launch, walking routes must be sampled; later launches reuse a compressed navigation cache. The cache is invalidated when the build revision or saved town layout changes. Other map assets still need to load; the first launch is not instant.

Touch controls: left pad moves, drag the right side to look, Run toggles running, Jump jumps, Use interacts with nearby doors/furniture/items, Talk starts or closes a nearby conversation, View changes perspective, and Menu expands the town controls. Hold Use for workbench tasks. Android starts with Performance graphics and 512-pixel texture import limits. A real phone performance check is still required.

**Activities** opens nearby seats, beds, meals, a kitchen when in reach, and storage at your home. On desktop, press **G** for the same list. Cooking and social options lead to their existing recipes, supplies, skills, and relationship systems. The **Controls** button adjusts touch-control size, look sensitivity, joystick dead zone, and vertical inversion; choices are saved on the device. Movement resets when a conversation or activity panel opens and when the app loses focus. Use also enters and leaves the player's home.

Interaction prompts name the selected person, door, seat, bed, or mission item. The phone Use button displays the action, while the world prompt supplies the target's name. Conversations show a named recipient in the panel and gold markers beside participating residents; group conversations identify a specifically selected recipient.

The industrial district keeps its compact, baked collision scene and working doors loaded. Its visual model loads in the background when the player or camera approaches and unloads farther away. Quality controls adjust the approach distance, with a wider unload distance to prevent repeated loading near the boundary. NPC routes and door state survive visual unloads. Regenerate the collision scene with `Godot --headless --path game --script res://bake_industrial_collision.gd` if the industrial source model changes. Other districts still load at startup; this is the first district converted to streaming.

Jobs, family routines, market transactions, missions and movement are local game systems. Free-form generated conversation, transcription and neural voices use the existing PC services over the same private Wi-Fi:

1. On the PC, open **Start Phone AI.cmd** and keep its window open. This starts the existing local AI/voice services and a paired LAN bridge on port 34322.
2. In the Android game, select **Connect to PC AI** and paste the connection address displayed by that window. The pairing code is stored only on the PC and phone, excluded from Git.
3. If Windows requests network access, permit it for your private network. Do not expose port 34322 to the internet. Without the PC connection, the town remains playable but generated dialogue and neural speech are unavailable.

The bridge accepts only its fixed AI/voice endpoints and requires the pairing code. It proxies to loopback services; it is not a general URL or file proxy. Windows Python, downloaded neural models, private histories, recordings, keystores and personal saves are not included in the APK or Git repository.

The Android project retains the same third-party asset attributions and restrictions. In particular, noncommercial assets do not become commercially licensed because they are packaged for Android. See the asset credit files before any distribution.
